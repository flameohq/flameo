Methodology

How the benchmark was run.

01

GitHub Actions

Ubuntu runner with PostgreSQL 16 and Python 3.12.

02

Load

300 concurrent connections, 2 wrk threads, 30s per scenario and a 3s warmup.

03

Servers

Granian 2.5.4 with one worker for Flameo RSGI, Flameo ASGI, FastAPI and Sanic. Robyn runs on its native server.

Test suite

The five tests.

01

Simple JSON

GET /json returns {"message":"Hello, world!"}.

02

Large JSON

GET /json/nested returns the 33,611-byte nested payload shown below.

03

Single Select Query

GET /db/employee/5 runs the single-row join and returns one employee row.

SELECT E.id, E.name, D.name AS department_name,
E.contact_no FROM employee E
JOIN department D ON D.id = E.department_id
WHERE E.id = 5;
04

List Select Query

GET /db/employees runs the same join with LIMIT 20 and returns 20 rows.

SELECT E.id, E.name, D.name AS department_name,
E.contact_no FROM employee E
JOIN department D ON D.id = E.department_id
ORDER BY E.id
LIMIT 20;
05

HTML Template

GET /html renders a light theme with two string variables and a count of 100, looping 100 times.

Template

Two strings. One number. 100 rows.

The template is shared by every framework. It receives title and subtitle as strings and count = 100 as a number.

Open benchmarks/template.html

  • title: Modern UI, rendered fast
  • subtitle: A light theme template with two strings and a 100-row loop.
  • count: 100
  • Loop: for i in range(1, count + 1)
template.html 
<h1>{{ title }}</h1>
<p class="subtitle">{{ subtitle }}</p>
<div class="badge">{{ count }} rows rendered</div>

{% for i in range(1, count + 1) %}
<div class="item" data-row="{{ i }}">
  <span class="dot"></span>
  <span class="num">{{ i }}</span>
  <span>Benchmark row {{ i }}</span>
</div>
{% endfor %}
